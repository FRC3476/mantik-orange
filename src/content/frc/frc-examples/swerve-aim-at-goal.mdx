### Overview

**Heading** is the direction the robot faces on the field. This lesson writes a command that points drivetrain +X at a floor target.

The target is a field `Translation2d` from `FieldConstants.getGoal()`. The robot pose comes from fused `drivetrain.getStateCopy().Pose`. Translation stays on the sticks, or is zero for rotate-in-place. Heading is owned by `SwerveRequest.FieldCentricFacingAngle`, which runs its heading controller with the request on the odometry thread.

This is not module-steering PID, not camera `tx`/`ty` lock, and not a 20 ms `PIDController` that commands ω.

API versions: **WPILib 2026.2.2**, **Phoenix 6 26.3.0**.

### Prerequisites

Tuner X `CommandSwerveDrivetrain`, fused pose, and a teleop-gated FieldCentric default command must already work.

### Geometry

Reuse the shot table's fictional `FieldConstants`: `kBlueGoal`, `kRedGoal`, and `getGoal()` every loop. The numbers are placeholders. Replace them from the season field. Select the alliance goal. Do not also flip the pose.

The command aims **drivetrain-origin +X**.

```java norun
Translation2d robotToGoal = goal.minus(pose.getTranslation());
Rotation2d desiredHeading = robotToGoal.getAngle();
double headingErrorRad = desiredHeading.minus(pose.getRotation()).getRadians();
```

`Translation2d.getAngle()` is `atan2(dy, dx)` in radians. WPILib heading is 0 along field +X. Positive rotation is counterclockwise.

Worked example: pose `(2.0, 3.0)` m, heading `0°`. Goal `(2.0, 7.0)` m. The vector is `(0.0, 4.0)`. `atan2(4.0, 0.0)` is `+90°`. Error is `+90°` (turn left).

Wrap example: current `+179°`, desired `−179°`. The short path is `+2°` through ±180°, not `−358°`. Phoenix 26.3.0 enables continuous input over ±π on the heading controller. `Rotation2d.minus` wraps the same way.

A rear- or side-facing shooter needs a **fixed yaw offset**. Offset implementation and turrets stay outside this baseline.

### FieldCentricFacingAngle

Configure heading gains and the omega cap explicitly. Phoenix 26.3.0 starts `HeadingController` at zero gains and `MaxAbsRotationalRate` at zero (uncapped). Keep rotational deadband **zero** so a joystick deadband cannot block small heading corrections.

```java
m_facing.withHeadingPID(headingP, 0.0, 0.0)
        .withMaxAbsRotationalRate(maxOmegaRadPerSec)
        .withForwardPerspective(ForwardPerspectiveValue.BlueAlliance)
        .withRotationalDeadband(0.0);
```

Field landmarks are blue-origin. Teleop `FieldCentric` stays on OperatorPerspective. Aiming at a field `Translation2d` must use `ForwardPerspectiveValue.BlueAlliance`. Do not rotate the target heading by operator forward a second time.

Reset `HeadingController` in `initialize`. Do not reset it every loop while a request is active.

Require **the drivetrain only**. `isFinished()` stays **false**. Inside tolerance means aligned, not finished. On `end` and when no goal is selected, `setControl` Idle so the last heading request does not keep running.

`isAligned()` lives on the aim command. Pass `aim::isAligned` into the shot table. It does not replace the shot table's stationary, dwell, and explicit-fire gates. Servoing heading while strafing is **not** a moving shot.

### AimAtGoalCommand

```java norun
package frc.robot.commands;

import com.ctre.phoenix6.swerve.SwerveModule.DriveRequestType;
import com.ctre.phoenix6.swerve.SwerveRequest;
import com.ctre.phoenix6.swerve.SwerveRequest.ForwardPerspectiveValue;
import edu.wpi.first.math.geometry.Pose2d;
import edu.wpi.first.math.geometry.Rotation2d;
import edu.wpi.first.math.geometry.Translation2d;
import edu.wpi.first.wpilibj.smartdashboard.SmartDashboard;
import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.constants.FieldConstants;
import frc.robot.subsystems.CommandSwerveDrivetrain;
import java.util.Optional;
import java.util.function.Supplier;

/**
 * Points drivetrain +X at the alliance goal using fused getState().Pose. Heading PID lives in
 * FieldCentricFacingAngle and runs with the request on the odometry thread.
 */
public class AimAtGoalCommand extends Command {
  public static final double kHeadingP = 3.0;
  public static final double kMaxOmegaRadPerSec = 4.0;
  public static final double kAlignedTolRad = Math.toRadians(3.0);

  private final CommandSwerveDrivetrain m_drivetrain;
  private final Supplier<Translation2d> m_fieldSpeedsMps;

  private final SwerveRequest.FieldCentricFacingAngle m_facing =
      new SwerveRequest.FieldCentricFacingAngle()
          .withDriveRequestType(DriveRequestType.OpenLoopVoltage)
          .withForwardPerspective(ForwardPerspectiveValue.BlueAlliance)
          .withRotationalDeadband(0.0)
          .withHeadingPID(kHeadingP, 0.0, 0.0)
          .withMaxAbsRotationalRate(kMaxOmegaRadPerSec);
  private final SwerveRequest.Idle m_idle = new SwerveRequest.Idle();

  /** Rotate in place. */
  public AimAtGoalCommand(CommandSwerveDrivetrain drivetrain) {
    this(drivetrain, Translation2d::new);
  }

  /** Aim while the driver translates. Speeds must already be blue-frame m/s. */
  public AimAtGoalCommand(
      CommandSwerveDrivetrain drivetrain, Supplier<Translation2d> fieldSpeedsMps) {
    m_drivetrain = drivetrain;
    m_fieldSpeedsMps = fieldSpeedsMps;
    addRequirements(drivetrain);
  }

  @Override
  public void initialize() {
    m_facing.HeadingController.reset();
  }

  @Override
  public void execute() {
    Optional<Rotation2d> heading = headingToGoal();
    if (heading.isEmpty()) {
      m_drivetrain.setControl(m_idle);
      SmartDashboard.putBoolean("AimAtGoal/aligned", false);
      SmartDashboard.putNumber("AimAtGoal/headingErrorDeg", Double.NaN);
      return;
    }

    Translation2d v = m_fieldSpeedsMps.get();
    m_drivetrain.setControl(
        m_facing
            .withVelocityX(v.getX())
            .withVelocityY(v.getY())
            .withTargetDirection(heading.get()));
    SmartDashboard.putNumber("AimAtGoal/headingErrorDeg", Math.toDegrees(headingErrorRad()));
    SmartDashboard.putBoolean("AimAtGoal/aligned", isAligned());
  }

  @Override
  public void end(boolean interrupted) {
    m_drivetrain.setControl(m_idle);
  }

  @Override
  public boolean isFinished() {
    return false;
  }

  public boolean isAligned() {
    if (!isScheduled()) {
      return false;
    }
    double error = headingErrorRad();
    return Double.isFinite(error) && Math.abs(error) <= kAlignedTolRad;
  }

  private Optional<Rotation2d> headingToGoal() {
    Pose2d pose = m_drivetrain.getStateCopy().Pose;
    return FieldConstants.getGoal().map(goal -> goal.minus(pose.getTranslation()).getAngle());
  }

  private double headingErrorRad() {
    Pose2d pose = m_drivetrain.getStateCopy().Pose;
    return headingToGoal()
        .map(desired -> desired.minus(pose.getRotation()).getRadians())
        .orElse(Double.NaN);
  }
}
```

### Step A — rotate in place

The one-argument constructor passes a zero translation supplier. **Right bumper** holds aim. Left bumper is heading seed on the swerve page — do not bind both to the same button.

```java norun
AimAtGoalCommand aim = new AimAtGoalCommand(drivetrain);
m_joystick.rightBumper().and(RobotModeTriggers.teleop()).whileTrue(aim);
```

On a PS controller the same hold is `R1()`.

### Step B — aim while translating

Rotate driver XY using `drivetrain.getOperatorForwardDirection()`, the same perspective already latched by generated `CommandSwerveDrivetrain.periodic()`. Pass those blue-frame m/s into the BlueAlliance facing-angle request. Do not convert pose or goal a second time.

```java norun
AimAtGoalCommand aim = new AimAtGoalCommand(drivetrain, this::teleopFieldSpeeds);
m_joystick.rightBumper().and(RobotModeTriggers.teleop()).whileTrue(aim);
```

```java norun
private static final double kAimMaxSpeed = 1.5;

private Translation2d teleopFieldSpeeds() {
    double x = MathUtil.applyDeadband(-m_joystick.getLeftY(), 0.1) * kAimMaxSpeed;
    double y = MathUtil.applyDeadband(-m_joystick.getLeftX(), 0.1) * kAimMaxSpeed;
    return new Translation2d(x, y).rotateBy(drivetrain.getOperatorForwardDirection());
}
```

Keep **one** `AimAtGoalCommand` instance. Default FieldCentric drive stays installed and resumes after `end()`. Bind the [Shooter Shot Table](/frc/shooter-shot-table) command in parallel on the same hold and pass `aim::isAligned`. Pose trust stays on the shot table, not on this heading command.

### Common mistakes

<RulesBox title="Heading aim mistakes">

- Reversed robot-to-goal vector, or `atan2(dx, dy)`.
- Operator perspective on a blue-origin target heading.
- Leaving Phoenix heading kP and max ω at the 26.3.0 zeros.
- A joystick rotational deadband on the facing-angle request.
- Camera `tx` or gyro-only yaw instead of fused pose.
- Raw joystick axes passed as m/s.

</RulesBox>
