### What you actually need

Entry-level problems rarely require a clever data structure. They require choosing a reasonable one and using it without bugs. In practice that means arrays, `ArrayList`, and occasionally a `HashMap` or `HashSet`.

Knowing when each one is the right tool is more valuable at this level than knowing how any of them work internally.

### Arrays

A fixed-size block of values. This is the default choice whenever you know the size in advance, which in contests you usually do because the input tells you.

```java
int n = nextInt();
int[] a = new int[n];
for (int i = 0; i < n; i++) {
    a[i] = nextInt();
}
```

Arrays are the fastest option and the smallest in memory. Reach for something else only when you need behavior an array does not have.

<RulesBox title="Array facts worth having memorized">

- `a.length` is a field, not a method — no parentheses.
- Indices run from `0` to `a.length - 1`. Problems often number things from 1, which is a common source of off-by-one bugs.
- New arrays are zero-filled (`0`, `0.0`, `false`, `null`). You do not need to initialize them yourself.
- `Arrays.fill(a, -1)` sets every element, which is useful for "not visited yet" markers.
- `Arrays.sort(a)` sorts in place, ascending, in O(N log N).

</RulesBox>

Two-dimensional arrays handle grids, which appear constantly:

```java
int rows = nextInt(), cols = nextInt();
char[][] grid = new char[rows][cols];
for (int r = 0; r < rows; r++) {
    String line = in.readLine();
    for (int c = 0; c < cols; c++) {
        grid[r][c] = line.charAt(c);
    }
}
```

Note the index order: `grid[row][col]`. Mixing this up produces an out-of-bounds error on non-square grids and a silently wrong answer on square ones.

### Handling 1-based input

Problems frequently describe input as "cow 1 through cow N". You have two options, and the second is usually less error-prone.

```java
// Option A: shift on read. Compact, but every later use must remember the shift.
int[] a = new int[n];
for (int i = 0; i < n; i++) a[i] = nextInt();

// Option B: allocate one extra slot and ignore index 0.
int[] a = new int[n + 1];
for (int i = 1; i <= n; i++) a[i] = nextInt();
```

Option B costs four bytes and removes an entire class of bug, because your code's indices match the problem statement's numbering exactly. For graph problems especially, this is worth doing by default.

### ArrayList

A resizable array. Use it when you do not know how many items you will end up with.

```java
List<Integer> results = new ArrayList<>();
for (int i = 0; i < n; i++) {
    if (a[i] % 2 == 0) {
        results.add(a[i]);
    }
}
System.out.println(results.size());
```

<ContentTable
  title="ArrayList costs"
  headers={["Operation", "Cost", "Note"]}
  rows={[
    ["<code>add(x)</code>", "O(1) amortized", "Appends at the end"],
    ["<code>get(i)</code>", "O(1)", "Direct index access"],
    ["<code>set(i, x)</code>", "O(1)", ""],
    ["<code>remove(i)</code>", "O(N)", "Shifts everything after <code>i</code>"],
    ["<code>contains(x)</code>", "O(N)", "Scans linearly &mdash; use a set instead"],
    ["<code>size()</code>", "O(1)", ""]
  ]}
/>

The two rows to notice are `remove` and `contains`. Calling `contains` inside a loop turns an O(N) algorithm into O(N<sup>2</sup>), which is the most common accidental slowdown at this level. If you need membership checks, use a `HashSet`.

<RulesBox title="ArrayList stores objects, not primitives">

`List<Integer>` boxes every value into an `Integer` object. That costs memory and time, and it changes how equality works:

```java
Integer x = 1000, y = 1000;
System.out.println(x == y);        // false — compares references
System.out.println(x.equals(y));   // true  — compares values
```

For values in a hot loop or a million-element collection, use `int[]` instead. When you genuinely need a growable list of ints, an `int[]` with a manual size counter works and is faster:

```java
int[] buf = new int[n];
int len = 0;
buf[len++] = value;
```

</RulesBox>

### HashSet and HashMap

`HashSet` answers "have I seen this before" in O(1) average time. `HashMap` associates a key with a value in O(1) average time.

```java
Set<Integer> seen = new HashSet<>();
int duplicates = 0;
for (int i = 0; i < n; i++) {
    if (!seen.add(a[i])) {
        duplicates++;      // add returns false if already present
    }
}
```

`add` returning a boolean is convenient — it both inserts and tells you whether the value was new, so you do not need a separate `contains` call.

Counting occurrences is the most common `HashMap` pattern:

```java
Map<Integer, Integer> count = new HashMap<>();
for (int i = 0; i < n; i++) {
    count.merge(a[i], 1, Integer::sum);
}

for (Map.Entry<Integer, Integer> e : count.entrySet()) {
    System.out.println(e.getKey() + " appears " + e.getValue() + " times");
}
```

`merge(key, 1, Integer::sum)` adds 1 to the existing value, or inserts 1 if the key is absent. The longer form using `getOrDefault` does the same thing:

```java
count.put(a[i], count.getOrDefault(a[i], 0) + 1);
```

<RulesBox title="When an array beats a HashMap">

If the keys are integers within a known small range, use an array. It is faster, uses far less memory, and cannot have hashing problems.

```java
// Values are guaranteed between 1 and 100
int[] count = new int[101];
for (int i = 0; i < n; i++) {
    count[a[i]]++;
}
```

This is called a frequency array or counting array, and it turns up in a large fraction of entry-level problems.

</RulesBox>

### Choosing

<ContentTable
  title="Which structure"
  headers={["You need", "Use"]}
  rows={[
    ["Fixed-size sequence, known length", "<code>int[]</code>"],
    ["Growable sequence", "<code>ArrayList</code>, or <code>int[]</code> with a counter"],
    ["Fast membership test", "<code>HashSet</code>"],
    ["Key &rarr; value lookup", "<code>HashMap</code>"],
    ["Counts of small integers", "<code>int[]</code> frequency array"],
    ["Sorted order maintained, or need min/max", "<code>TreeSet</code> / <code>TreeMap</code>"],
    ["Repeatedly extract the smallest", "<code>PriorityQueue</code>"],
    ["A grid", "<code>char[][]</code> or <code>int[][]</code>"]
  ]}
/>

The last two go beyond the basics, but knowing they exist helps you recognize when a simpler approach is not going to be enough.

<ExerciseBox title="Practice" description="Write each of these. They are all short, and all appear as sub-steps of real problems.">

1. Read N integers and print how many distinct values there are.
2. Read N integers between 1 and 1000 and print the value that appears most often.
3. Read a grid of `.` and `#` characters and print the number of `#`.
4. Read N integers and print them in the order they first appeared, with duplicates removed.
5. Read N integers and print the second largest distinct value.

<details>
<summary>Hints</summary>

1. `HashSet` — the size after adding everything.
2. Frequency array of size 1001, then scan for the maximum count.
3. Nested loop over the grid; count matches.
4. A `HashSet` to track seen values plus an `ArrayList` to record order.
5. Either sort and scan backwards past duplicates, or track the top two in one pass. The one-pass version is worth writing — it forces you to handle the case where all values are equal.

</details>

</ExerciseBox>
