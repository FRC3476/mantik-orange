### Calibration

Fusion cannot fix a wrong wheel diameter or a camera bolted 10 cm from where the code thinks it is. Calibrate the sensors, then tune uncertainties.

### Wheel diameter and encoder distance

Measure the wheel you actually drive on. Manufacturer diameter is a starting guess.

Encoder distance per revolution depends on **which shaft** the encoder reads. A wheel-shaft encoder uses wheel circumference directly. A motor-shaft encoder must include the gear ratio between motor and wheel:

```java
double distancePerMotorRotation =
    (measuredWheelDiameterMeters * Math.PI) / gearRatioMotorToWheel;
```

If you skip the gear ratio on a geared encoder, every odometry update is wrong by that factor.

### Track width and wheelbase

For swerve, measure track width and wheelbase used in kinematics. Heading error grows quickly if those numbers are off.

### Five separate calibrations

Keep these distinct:

1. **Lens calibration** — PhotonVision or Limelight camera calibrator (distortion, intrinsics).
2. **Mount transform** — tape measure and `Transform3d` / Limelight camera pose.
3. **Field map** — welded vs AndyMark, matching UI and `AprilTagFieldLayout`.
4. **Drivetrain** — wheel diameter, gearing, module order, gyro.
5. **Uncertainty** — vision and odometry stddevs.

Stddevs cannot repair the first four.

### Vision calibration (UI)

**PhotonVision:** run the in-UI calibrator at the same resolution you will use in a match. Recheck after a lens or camera change. See [camera calibration](https://docs.photonvision.org/en/latest/docs/quick-start/camera-calibration.html).

**Limelight:** use the Limelight calibration / pipeline tools in the UI. Keep the mount in the UI identical to any `setCameraPose_RobotSpace` call.

Mount numbers belong in one place. Replace the example with your measurements.

### Comparing cached vision to a tape measure

Call this only after `Drive` has already polled this loop. It reads diagnostics, not the camera queue.

```java
public void logVisionAccuracy(Pose2d measuredPose, double nowSeconds) {
    VisionDiagnostics diagnostics = m_vision.getDiagnostics(nowSeconds);
    SmartDashboard.putBoolean("Vision Current Valid", diagnostics.currentValid);
    SmartDashboard.putNumber("Vision Age (s)",
        diagnostics.ageSeconds == null ? -1.0 : diagnostics.ageSeconds);
    SmartDashboard.putString("Vision Solve", diagnostics.solveLabel);
    SmartDashboard.putNumber("Vision Tags Used", diagnostics.tagsUsed);
    SmartDashboard.putString("Vision Reject", diagnostics.lastRejectReason);

    Pose2d fused = m_poseEstimator.getEstimatedPosition();
    SmartDashboard.putNumber("Fused X Error (m)",
        Math.abs(fused.getX() - measuredPose.getX()));
    SmartDashboard.putNumber("Fused Y Error (m)",
        Math.abs(fused.getY() - measuredPose.getY()));
}
```

Exercise near and far tags, one tag and several tags, translation and rotation, occlusion, and unplug/replug. Compile-time checks are not measured robot accuracy.

### Fusion stddevs

If odometry is well calibrated, you can lower state stddevs. If MultiTag at close range is trustworthy, you can lower the MultiTag vision stddevs. If single-tag heading is noisy, keep the large heading stddev. Record what you measured; do not copy these numbers as answers.

```java
var stateStdDevs = VecBuilder.fill(0.05, 0.05, 0.05);
```

The complete `Drive` class from the fusion lesson already inserts vision with the three-argument `addVisionMeasurement` and the same quality policy as `VisionSubsystem`. Do not ship a calibration copy that skips ambiguity and distance checks.
