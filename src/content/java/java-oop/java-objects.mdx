### More than one from the same class

A class is the recipe. Each `new` makes a **different** object. Two robots can share the same methods and still hold different names and battery values.

That is the reason to use objects: you are not copying a new set of variables for every robot.

```java
class Bot {
    String name;
    int battery = 100;

    Bot(String name) {
        this.name = name;
    }

    void drain(int amount) {
        battery = battery - amount;
    }
}

public class Main {
    public static void main(String[] args) {
        Bot alpha = new Bot("Alpha");
        Bot beta = new Bot("Beta");

        alpha.drain(20);

        System.out.println(alpha.name + " " + alpha.battery);
        System.out.println(beta.name + " " + beta.battery);
    }
}
```

`alpha.drain(20)` changes only Alpha. Beta still has 100. Same class, two states.

### What to print

`System.out.println(alpha)` without extra work prints a class name and a memory id, which is not useful. Print fields (`alpha.name`) or write a method that returns a string of those fields. `toString` is a later convenience, not required here.

- Do not worry yet whether two variables point at the **same** object. That is [Objects and References](/java/java-objects-references)
