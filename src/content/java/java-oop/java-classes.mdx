### A recipe, not the robot

A **class** is a recipe. It lists the data an object will hold (**fields**) and the actions it can take (**methods**).

An **object** is one thing built from that recipe. `new` is how you build it.

You already used classes Java provides (`String`, later `ArrayList`). Here you write your own so related data stays together — a team member’s name and role, a counter’s value — instead of a pile of loose variables.

```java
class Counter {
    int value;

    Counter() {
        value = 0;
    }

    void add(int n) {
        value = value + n;
    }

    int get() {
        return value;
    }
}

public class Main {
    public static void main(String[] args) {
        Counter c = new Counter();
        c.add(1);
        c.add(2);
        System.out.println(c.get());
    }
}
```

The class is `Counter`. `c` is one object. `c.add(1)` runs `add` on **that** object’s `value`.

### Constructors

A **constructor** is the method that runs when you write `new Counter()`. Its name matches the class. It has no return type.

Use it to give fields their first values.

### this

Inside the class, `this` means **the object on the left of the dot**.

You need it when a parameter has the same name as a field:

```java
class TeamMember {
    String name;

    TeamMember(String name) {
        this.name = name;  // field = parameter
    }
}
```

Without `this`, `name = name` would assign the parameter to itself and leave the field untouched.

<RulesBox title="Class vs object">

The class is shared. Each `new` makes a **separate** object with its own field values. Two `TeamMember` objects can have different names.

Methods you write on a class are **instance** methods. They are not `static`. Call them on an object: `member.getName()`, not `TeamMember.getName()`.

`private` on a field means other classes must use methods to read or change it. That is **encapsulation**. The playground `Counter` uses `private int value` so `main` cannot say `c.value = 99`.

</RulesBox>
