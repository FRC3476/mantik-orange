### The variable is not the object

When you write `Bot a = new Bot()`, `a` does not contain the object. It holds a **reference** — an arrow to the object in memory.

Assignment copies the arrow, not the object. Two names can point at the same thing.

```java
class Cell {
    int value;
}

public class Main {
    public static void main(String[] args) {
        Cell a = new Cell();
        Cell b = a;
        a.value = 5;
        System.out.println(b.value);
    }
}
```

That prints `5`. There is one `Cell`. `a` and `b` are two names for it.

`==` is true when both variables point at that same object. Two `new Cell()` calls make two objects, so `==` is false even if both `value` fields happen to be `0`.

Writing `equals` so two different objects count as “the same team” is later. Until then, `==` means same object.

### null

A reference can point at **nothing**. The name for that is `null`. Calling a method on `null` crashes with `NullPointerException`.

```java
Cell c = null;
if (c != null) {
    System.out.println(c.value);
} else {
    System.out.println("no cell");
}
```

Check before you use the object. Printing `c` when it is `null` prints the word `null` and does not crash.

### Parameters copy the arrow

A method parameter is a second name for the same object. Changing a **field** inside the method is visible to the caller. Pointing the parameter at a `new` object is not — that only changes the local name.

```java
class Cell {
    int value;
}

public class Main {
    static void bump(Cell c) {
        c.value = c.value + 1;
    }

    static void replace(Cell c) {
        c = new Cell();
        c.value = 99;
    }

    public static void main(String[] args) {
        Cell a = new Cell();
        a.value = 1;
        bump(a);
        System.out.println(a.value);  // 2
        replace(a);
        System.out.println(a.value);  // still 2
    }
}
```

`bump` changes the object. `replace` builds a different object and leaves `a` alone.

A method can **return** a reference, including a newly built object, if the caller should receive a different arrow.

<RulesBox title="Reference rules">

- `Cell b = a` does not copy `value`. It copies the arrow
- `null` means no object. Check before calling methods
- Changing fields through any name changes the one object
- Reassigning a parameter (`c = new Cell()`) does not reassign the caller’s variable

</RulesBox>
