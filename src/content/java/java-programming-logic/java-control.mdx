### One decision, several values

[Conditional Statements](/java/java-conditionals) taught `if` / `else if` / `else`. [Java Methods](/java/java-methods) taught naming a block of code and calling it.

This page puts them together. You write the decision **once** in a method, then call it with different numbers. You do not copy the same `if` chain three times.

Repeating work a unknown number of times is [While Loops](/java/java-while-loops). Do not use `for` or `while` here.

### A method that returns a label

`zone` takes a distance and returns which label to print. `main` only calls it.

```java
public class Main {
    public static String zone(int distance) {
        if (distance > 20) {
            return "FAR";
        } else if (distance > 5) {
            return "NEAR";
        } else {
            return "STOP";
        }
    }

    public static void main(String[] args) {
        System.out.println(zone(25));
        System.out.println(zone(12));
        System.out.println(zone(3));
    }
}
```

Order of the tests matters. If you check `distance > 5` first, `25` would print `NEAR` and never reach `FAR`.

`return` leaves the method immediately. After `return "FAR"` the later `else if` does not run.

### Why a method

If auto and teleop both need the same distance rule, they call `zone`. A bug in the thresholds is fixed in one place.

Keep the method `public static` for now, the same as the methods lesson. Instance methods wait until [Java Classes](/java/java-classes).

<RulesBox title="Reuse the comparison operators">

`=` still assigns. `==` still compares. Putting the chain in a method does not change that.

`&&` / `||` from conditionals still work inside the method if you need two facts at once (battery high **and** not e-stopped).

</RulesBox>
