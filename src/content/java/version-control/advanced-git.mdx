### Tools that can delete work

This page is optional. Use a **throwaway repo**, never `main` on the competition robot, while you try these commands.

On a branch other people already pulled, prefer **revert**. `reset --hard` throws away uncommitted work and can drop commits. Do not run it because a web page said to.

### revert vs reset

- **`git revert HEAD`** — makes a **new** commit that undoes the last one. Safe on `main` the team shares
- **`git reset`** — moves this branch pointer. Fine for a commit you have **not** pushed. After you push, reset rewrites history others may have cloned

```
git revert HEAD
```

To throw away **uncommitted** edits in one file (keep the last commit):

```
git restore notes.txt
```

Older docs say `git checkout -- notes.txt`. Same idea; `restore` is the current name.

`git reset --hard` discards uncommitted changes **and** can drop commits. If you need it, run `git status` first and be sure you can lose what you see.

### stash

Unfinished work that is not ready to commit, but you need a clean tree (to pull, or to switch branches):

```
git stash
git status
git stash pop
```

`stash list` shows saved piles. Practice this on the throwaway folder from [Local Git Workflow](/java/local-workflow).

### rebase vs merge

**Merge** adds a merge commit and keeps both histories. **Rebase** replays your commits on top of another branch and **rewrites** those commits.

Do not rebase `main` (or any branch teammates already pulled). If you rebase, do it only on a local feature branch that only you use. [Branching and Merging](/java/branching-merging) is enough for most teams.

### Tags for a frozen robot

A **tag** names a commit, for example the code you inspected with.

```
git tag -a inspect-ready -m "Code at inspection"
```

Push tags only when the team agrees (`git push origin inspect-ready`). GitHub **releases** can point at a tag. That is more useful than Git Flow, environment branches, or feature flags for a high-school robot.

<RulesBox title="Safety">

- Shared `main`: revert, not hard reset
- Unpushed local commit you regret: reset is possible; ask a mentor the first time
- Never `--hard` on a dirty robot repo “to see what happens”
- Rebase is optional. Merge is the default

</RulesBox>

<ExerciseBox title="Throwaway repo only">

1. In a practice repo, make a commit, then `git stash` after a new edit. Confirm `git status` is clean. `git stash pop` and confirm the edit returns.
2. Make a commit whose message you are willing to undo. `git revert HEAD`. Confirm `git log` shows the revert commit and the old files match the earlier snapshot.

Do not practice `reset --hard` on team code.

</ExerciseBox>
