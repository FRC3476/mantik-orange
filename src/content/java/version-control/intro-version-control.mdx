### A history of the robot code

**Version control** is a record of snapshots of your files. Each snapshot is a **commit**. You can see what changed, go back to a working teleop, and work next to someone else without emailing zip files.

This module sits last in the Java sidebar so it does not interrupt learning the language. If two people already share a robot repo, start here now. You do not need concurrency first.

### A short story

Two programmers edit autonomous. One change breaks the park. Yesterday’s code still worked. With version control you check out yesterday’s commit and the robot parks again. Without it, you hope someone has a copy on a laptop.

That is the purpose: undo, history, and sharing.

### Git vs GitHub

- **Git** runs on your computer. It stores the history in a hidden `.git` folder.
- **GitHub** is a website that hosts a copy of that history so the team can push, pull, and review.

You can use Git with no GitHub. You cannot use GitHub as a substitute for Git — the site talks to Git.

**Commit** saves a snapshot on **this** computer. **Push** (next lessons) sends commits to GitHub. Saving in your editor is not a commit.

- Open the team repo on GitHub if you have one. Find the newest commit message. That message is the history you are about to learn to write.
