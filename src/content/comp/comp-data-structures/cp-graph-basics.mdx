### Recognizing a graph

A graph is a set of things and a set of connections between them. The word "graph" almost never appears in the problem statement. What appears instead is:

- Cows that are friends with other cows
- Rooms connected by doors
- Cities joined by roads
- Fields where you can walk between adjacent ones
- Tasks where one must finish before another

All of these are graphs. The things are **nodes** (also called vertices), and the connections are **edges**.

<RulesBox title="Vocabulary you need">

- **Undirected** — the connection works both ways. Friendship, roads.
- **Directed** — one way only. Prerequisites, one-way streets.
- **Weighted** — edges carry a number, such as a distance or cost.
- **Degree** — how many edges touch a node.
- **Connected component** — a maximal group of nodes all reachable from each other.
- **Path** — a sequence of nodes each joined to the next.
- **Cycle** — a path that returns to where it started.

</RulesBox>

### Storing a graph

The standard choice is an **adjacency list**: for each node, the list of its neighbours.

```java
int n = nextInt();          // nodes, numbered 1..n
int m = nextInt();          // edges

List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i <= n; i++) {
    adj.add(new ArrayList<>());
}

for (int e = 0; e < m; e++) {
    int u = nextInt();
    int v = nextInt();
    adj.get(u).add(v);
    adj.get(v).add(u);      // both directions — omit this line if directed
}
```

Allocating `n + 1` lists and ignoring index 0 lets node numbers match the input's 1-based numbering, which removes a whole class of off-by-one bug.

The single most common graph bug is adding only one direction for an undirected graph. If a traversal reaches fewer nodes than expected, check this first.

Use an adjacency list by default. A matrix is reasonable only when N is at most a few thousand and you need constant-time edge queries — `boolean[n+1][n+1]` at N = 5,000 is 25 million booleans, about 25 MB, which is near the practical limit.

### Depth-first search

The basic traversal. Visit a node, then recursively visit every unvisited neighbour.

```java
static boolean[] visited;
static List<List<Integer>> adj;

static void dfs(int u) {
    visited[u] = true;
    for (int v : adj.get(u)) {
        if (!visited[v]) {
            dfs(v);
        }
    }
}
```

Marking `visited[u]` at the start of the call, before recursing, is essential. Marking it after the loop causes infinite recursion on any graph with a cycle.

### Counting connected components

The archetypal introductory graph problem. Start a traversal from every node that has not been reached yet; each start is one new component.

```java
visited = new boolean[n + 1];
int components = 0;

for (int i = 1; i <= n; i++) {
    if (!visited[i]) {
        components++;
        dfs(i);
    }
}

System.out.println(components);
```

The same skeleton answers many questions — change what `dfs` records:

- Size of each component: count nodes as you visit them.
- Largest component: track the maximum of those sizes.
- Are `a` and `b` connected: run one DFS from `a`, then test `visited[b]`.
- Is the whole graph connected: one DFS from node 1, then check that every node is visited.

### Breadth-first search

BFS visits nodes in order of distance from the start, using a queue instead of recursion. For unweighted graphs it gives shortest paths, measured in number of edges.

```java
static int[] bfs(int start, int n) {
    int[] dist = new int[n + 1];
    Arrays.fill(dist, -1);          // -1 means unreachable

    Deque<Integer> queue = new ArrayDeque<>();
    dist[start] = 0;
    queue.add(start);

    while (!queue.isEmpty()) {
        int u = queue.poll();
        for (int v : adj.get(u)) {
            if (dist[v] == -1) {
                dist[v] = dist[u] + 1;
                queue.add(v);
            }
        }
    }
    return dist;
}
```

`ArrayDeque` is the queue to use. `LinkedList` also implements `Deque` but is slower and uses more memory.

Here `dist` doubles as the visited marker: `-1` means not yet reached. Setting `dist[v]` at the moment you enqueue — not when you dequeue — is what prevents a node being added twice.

<RulesBox title="DFS or BFS?">

- **Connectivity, components, cycle detection** — either works. DFS is shorter.
- **Shortest path in an unweighted graph** — BFS. DFS does not give shortest paths.
- **Very deep graphs** — BFS, or an iterative DFS. Recursive DFS can overflow the stack past roughly 10,000 levels.

For weighted graphs neither is enough; that is Dijkstra, covered in Shortest Paths.

</RulesBox>

### Grids are graphs

A grid problem is a graph problem where the nodes are cells and the edges join adjacent cells. You do not need to build an adjacency list — the neighbours are computed.

*Count the regions of connected `.` cells in a grid.*

```java
static char[][] grid;
static boolean[][] seen;
static int rows, cols;
static int[] dr = {-1, 1, 0, 0};
static int[] dc = {0, 0, -1, 1};

static void fill(int r, int c) {
    seen[r][c] = true;
    for (int d = 0; d < 4; d++) {
        int nr = r + dr[d], nc = c + dc[d];
        if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
        if (seen[nr][nc] || grid[nr][nc] != '.') continue;
        fill(nr, nc);
    }
}

// then, in main:
int regions = 0;
for (int r = 0; r < rows; r++) {
    for (int c = 0; c < cols; c++) {
        if (grid[r][c] == '.' && !seen[r][c]) {
            regions++;
            fill(r, c);
        }
    }
}
```

The bounds check must come before reading `grid[nr][nc]`, or you get an out-of-bounds error. This technique has its own name and its own lesson: Flood Fill.

<RulesBox title="Grid traversal notes">

- The offset arrays give the four orthogonal neighbours. For eight-directional movement, use all nine combinations of `-1, 0, 1` except `(0, 0)`.
- A 1,000 × 1,000 grid has a million cells. A recursive fill can reach a million deep on a snake-shaped region and overflow the stack — use BFS with a queue for large grids.

</RulesBox>

1. Given an undirected graph, print the number of connected components.
2. Given an undirected graph, print the size of the largest component.
3. Given a grid of `.` and `#`, print the number of connected regions of `.` cells.
