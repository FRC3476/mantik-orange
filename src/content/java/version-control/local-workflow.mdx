### Three places Git cares about

1. **Working tree** — the files you edit
2. **Staging area** — the exact changes you chose for the next snapshot
3. **Repository** — the commits, stored in a hidden `.git` folder

A **commit** is a snapshot in the repository on **this computer**. It does not publish anything. Sending commits to GitHub is **push**, in [GitHub and Remote Repositories](/java/github-remotes).

**Clone** (copy an existing GitHub repo) also waits until remotes. This lesson starts from an empty folder.

### One throwaway repo

In a terminal, pick a folder that is **not** your competition robot.

```
mkdir git-practice
cd git-practice
git init
```

Create a file named `notes.txt` with one line of text (any editor). Then:

```
git status
git add notes.txt
git status
git commit -m "Add practice notes"
git log
```

After `git add`, status shows the file as staged. After `commit`, status is clean and `git log` shows your message.

`git add .` stages every change in the folder. Prefer naming the file until you know what `.` will include.

```
git diff
```

shows unstaged edits. `git diff --staged` shows what is already staged.

<RulesBox title="Commit vs save vs push">

- Save in the editor: the file on disk changed. Git does not know yet
- `git add` then `git commit`: Git recorded a snapshot locally
- `git push`: that snapshot goes to GitHub. You have not done this yet

If you only save, teammates cannot see the change, and you have no commit to revert to.

</RulesBox>

<ExerciseBox title="Practice on a throwaway folder">

1. `git init` in a new folder.
2. Add a file, `git add` it, `git commit -m "First commit"`.
3. Change the file, run `git status`. You should see it modified.
4. Commit again. `git log` should show two commits.
5. After the second commit, `git status` should say there is nothing to commit.

Do not run this on the team robot repo until you are comfortable.

</ExerciseBox>
