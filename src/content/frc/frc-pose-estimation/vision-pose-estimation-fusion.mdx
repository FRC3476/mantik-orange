### Sensor fusion

Odometry updates every robot loop from wheels and a gyro. Vision updates when a tag is visible. WPILib's `SwerveDrivePoseEstimator` combines both.

Vision is not a GPS lock. A tag can be wrong, late, or missing. Fusion is useful because odometry is always there and vision, when it passes the checks from the previous lesson, pulls the estimate back toward the field.

Learn more: [WPILib Pose Estimators](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/state-space/state-space-pose-estimators.html#pose-estimators)

### How the estimator weights measurements

Each `update()` from odometry and each `addVisionMeasurement()` from vision has a **standard deviation** (uncertainty) you configure. The filter computes a gain from those uncertainties. A smaller vision stddev trusts that measurement more.

The estimator does **not** automatically grow odometry uncertainty as time passes since the last tag. If vision has been gone for three seconds, the pose is whatever odometry integrated, with the stddevs you set.

`addVisionMeasurement(pose, timestamp, stdDevs)` uses the **capture** timestamp in WPILib's FPGA time base. PhotonLib and LimelightHelpers already compensate pipeline latency. Do not subtract latency again. A timestamp outside the pose buffer (default 1.5 s) or in the future is rejected.

Initialize odometry before the first vision insert. On `resetPose`, drop captures from before the reset. If the camera reconnects, do not replay stale queued frames.

When a measurement is rejected, keep running odometry. Report connection, age, and rejection reason. Do not display an old vision pose as current.

### Drive owns the estimator

Reuse the existing `Drive` gyro, module positions, kinematics, and `SwerveDrivePoseEstimator`. Module order is FL, FR, BL, BR — the same order as the kinematics constructor.

Do not construct a second gyro or a second estimator for vision.

```java
DriveHardware hardware = /* your existing Drive gyro + module positions */;
VisionSubsystem vision = new VisionSubsystem();
Drive drive = new Drive(hardware, vision);
```

```java
import edu.wpi.first.math.estimator.SwerveDrivePoseEstimator;
import edu.wpi.first.math.geometry.Pose2d;
import edu.wpi.first.math.kinematics.SwerveModulePosition;

m_poseEstimator = new SwerveDrivePoseEstimator(
    m_hardware.getKinematics(),
    m_hardware.getGyroRotation(),
    m_hardware.getModulePositions(),
    new Pose2d());
```

State stddevs (illustrative): `0.1, 0.1, 0.1` for x (m), y (m), heading (rad).

Vision stddevs come from `VisionEstimate` after quality checks: `0.3, 0.3, 0.9` for MultiTag and `0.5, 0.5, 2.0` for a single tag. Heading is intentionally weak so the gyro still dominates yaw. Measure better values on your robot. Use finite numbers. Do not use infinity as a way to reject a measurement.

### Periodic order

```java
@Override
public void periodic() {
    updateOdometry();
    updateVision();
    Pose2d pose = m_poseEstimator.getEstimatedPosition();
}
```

```java
public void updateOdometry() {
    m_freshness.markOdometryReady(Timer.getFPGATimestamp());
    m_poseEstimator.update(
        m_hardware.getGyroRotation(),
        m_hardware.getModulePositions());
}
```

### Adding vision measurements

`updateVision()` is the same Java for both vendors. `pollEstimates()` is the vendor difference.

<CodeTabs group="frc-vision">
<CodeTab label="PhotonVision" value="photonvision">

```java
public void updateVision() {
    double now = Timer.getFPGATimestamp();
    if (!m_vision.isCameraConnected()) {
        m_freshness.markDisconnect();
        m_vision.markDisconnected(now);
        return;
    }
    if (!m_freshness.isConnected()) {
        m_freshness.markReconnect();
    }

    // PhotonVision may return several captures. Insert each accepted one once.
    for (VisionEstimate estimate : m_vision.pollEstimates()) {
        var freshnessReject = m_freshness.reject(estimate.timestampSeconds, now);
        if (freshnessReject.isPresent()) {
            m_vision.recordFusionReject(freshnessReject.get(), now);
            continue;
        }
        m_freshness.accept(estimate.timestampSeconds);
        m_poseEstimator.addVisionMeasurement(
            estimate.pose,
            estimate.timestampSeconds,
            estimate.stdDevs);
        m_vision.recordFusionAccept(estimate, now);
    }
}
```

    }
}

</CodeTabs>

Freshness rejects duplicate or out-of-order timestamps, captures older than 0.5 s, timestamps ahead of FPGA time by more than 20 ms, captures older than the 1.5 s pose buffer, and captures from before the last `resetPose`.

Do not reject a measurement because it disagrees with the *current* pose while the robot is moving. Latency makes that comparison misleading.

### Reset

```java
public void resetPose(Pose2d newPose) {
    double now = Timer.getFPGATimestamp();
    m_freshness.markPoseReset(now);
    m_vision.notifyPoseReset(now);
    m_poseEstimator.resetPosition(
        m_hardware.getGyroRotation(),
        m_hardware.getModulePositions(),
        newPose);
}
```
